# navecher-web

Фронт сервиса «На вечер» — аренда вечерних нарядов из шкафов девушек, Москва. Модель — как у Pickle («Airbnb для гардероба»):
владелица выставляет вещь через Telegram-бота, арендатор находит её на сайте или в канале и запрашивает вечер.

Стек: **React 18 + TypeScript + Vite**. Данные — из API [navecher-api](https://github.com/IlushaSPB/navecher-api);
он же раздаёт собранный сайт.

## Что умеет

**Сайт** — основной вход. Режим «День / Вечер» по закату в Москве, каталог с фильтрами категорий (пустые скрыты)
и размеров (только те, что есть), вид «сетка / список», окно вещи (фото, замеры, описание, залог, метро, сколько раз сдавали,
«Арендовать» → бот, «Пожаловаться», ссылка на правила), «Сохранённое» в браузере, калькулятор для владелиц,
страница `/rules`. Ссылка на вещь `/#item-<id>` — ей можно делиться; «Назад» закрывает окно.
Яндекс Метрика (`METRIKA_ID` приходит из `/api/config`) с целями `rent_click` и `lend_click`.

**Прототип приложения** — `/app`: кликабельный прототип iOS/Android на живом каталоге; брони, чат и «Сдать вещь» — имитация в браузере.

## Структура

```
src/main.tsx                    вход: сайт (App.tsx) или прототип /app
src/components/                 блоки сайта: шапка, каталог, окно вещи, правила, FAQ…
src/proto/                      прототип приложения (/app)
src/api.ts                      типы и запросы к API, ссылки на бота
src/sun.ts, theme.ts            режим «День / Вечер» по закату
src/metrics.ts                  цели Яндекс Метрики
public/                         favicon, theme-init.js (тема до загрузки React), фото для сайта
.github/workflows/deploy.yml    CI/CD: типы и сборка → dist на VPS с проверкой и откатом
```

## Локальный запуск

Нужен запущенный бэкенд из [navecher-api](https://github.com/IlushaSPB/navecher-api) (`make run`, по умолчанию порт 8080).

```bash
npm ci
API_URL=http://localhost:8080 npm run dev   # http://localhost:5173, /api проксируется на Go-сервер
npm run build                               # проверка типов + сборка в dist/
```

Чтобы бэкенд отдавал сборку сам, держи репозитории рядом: navecher-api по умолчанию берёт `../navecher-web/dist`.

## Деплой

Любой push в `main`: проверка типов → сборка → `dist/` на сервер в `/opt/navecher/web` → проверка, что главная и её скрипт
отдаются; если нет — возвращается прошлая версия. Сервис не перезапускается: Go-сервер читает файлы с диска на каждый запрос.

Сервер готовит `deploy/setup-server.sh` из navecher-api. Секреты GitHub — те же, что там: `DEPLOY_HOST`, `DEPLOY_USER=deploy`,
`DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. В первый раз выкладывай сначала API, потом фронт.
